### Инфраструктура

Весь стенд можно поделить на условные две составляющие:
- **Административный сегмент** 
  Включает в себя компоненты, обеспечивающие управление и координацию работы всей системы:
  - Контроллер домена+DNS сервер
  - Semaphore UI
  - GitFlic
- **Целевой сегмент**
  Включает серверы, на которых непосредственно выполняются плейбуки Ansible, с различными операционными системами:
  - Хост с ОС Ubuntu
  - Хост с ОС RedOS
  - Хост с ОС Astra

### Задания
1. В рамках данного задания необходимо развернуть тестовый стенд, включающий установку и настройку всех необходимых серверов согласно заданной инфраструктуре. Следует произвести установку и базовую конфигурацию операционных систем на целевых серверах — Ubuntu, RedOS и Astra, обеспечив корректную работу сетевых служб. 
   Также важно настроить сетевую связанность между административным и целевым сегментами, включая настройку маршрутизации и правил взаимодействия, чтобы обеспечить стабильный доступ к DNS-серверу, контроллеру домена и другим сервисам административного сегмента. В завершение необходимо добавить в систему необходимые учетные записи пользователей, настроить для них права доступа и роли согласно требованиям безопасности, а также проверить возможность подключения и корректную работу этих учетных записей. 
2. Поднятие и настройка GitFlic
	Для выполнения данного задания необходимо поднять и базово настроить GitFlic. Более подробно можно посмотреть в статье [[Настройка GitFlic]]. 
	Также необходимо загрузить репозитории, необходимые для выполнения лабораторных работ: https://github.com/dev-sec/ansible-collection-hardening, astra_hardening (из файла, прикрепленного к лабораторной работе) 
3. Для выполнения третьего задания необходимо развернуть и настроить Semaphore:
	   1. Развернуть платформу при помощи контейнеризации. 
	      В качестве БД необходимо использовать PostgreSQL. 
	      В файле окружения необходимо указать корректные данные для ldap подключения к контроллеру домена. 
	      Для корректной конфигурации docker-compose.yaml можно использовать сайт-конфигуратор: https://semaphoreui.com/install/docker/2_12/. 
	   2. Тонкая настройка системы
	      1. Необходимо добавить доменные УЗ в систему, зайти под ними в веб интерфейс и посмотреть, какими полномочиями они наделены.
	      2. Создать проект `Lab` и добавить в него пользователей.
	      3. Создать ключи доступа:
	         - Для взаимодействия с репозиторием
	         - Для подключения к удаленным хостам (по ключу для пользователя ansible и по паролю для root)
	      4. Создать инвентарь и добавить в него необходимые хосты
	         
	         

|     |     |
| --- | --- |
|     |     |

	| Название       | Хосты                              |
	         |----------------|------------------------------------|
	         |astra_hosts|astra-client|
	         |full_hosts|astra-client, ubuntu-client, redos-client|
	         
	      5. Подключить все необходимые репозитории:
	         
	         | Название       | Ссылка                | Описание                     |
	         |----------------|-----------------------|------------------------------|
	         | ansible-collection-hardening       | [GitHub](https://github.com/dev-sec/ansible-collection-hardening) | Общие правила для обеспечения безопасности     |
	         |astra-hardening|прикрепленный архив|Набор ролей Ansible, обеспечивающих защиту ОС специально для Astra Linux Special Edition|
		  6. Создать шаблон для запуска плейбуков: для репозитория ansible-collection-hardening указать инвентарь full_hosts, для репозитория astra-hardening - astra_hosts.
	
4.  Проведение hardering системы
   Для выполнения данного задания необходимо на целевые хосты установить актуальную версию lynis - инструмента аудита для UNIX-подобных систем. После установки необходимо провести аудит и посмотреть результаты: процент защищенности системы и какие потенциально слабые места в безопасности присутствуют на хосте. Данные результаты необходимо записать в отдельный файл.
